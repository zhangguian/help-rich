05页面要表达的口径(实现必须与之一致)

  • 覆盖 16 只 = 自选 11 只(持仓 ∪ ★关注,持仓优先)+ 全市场滚动池 5 只,两段各自完整覆盖,不互相挤占。
  • 「达到预期」= 触及 或 执行;只有「未触发」才累计连续天数;「数据不足」不累计(不因缺数据惩罚股票)。
  • 连续 3 天未达预期 → 剔除,空出的席位由全市场 4 因子分最高的票补位;被剔的票当天不再补位回来。
  • 「最新操作要求」是唯一事实源:取该票 status_now == 'now' 的第一条(条件已满足、待执行);没有则显示第一条待触发预案的条件摘要。左栏锚点行与中栏票头显示同一份文案。
  • 池票在左栏带「池」徽章并标注保留 / 新补位与 4 因子分;被剔除的票也留在锚点栏里(标灰 + 剔除原因),便于回看「这只为什么被换掉」。
  • universe 口径写明在页面上:全市场 → 主板 → 非 ST → 成交额达标,不写「全市场选股」这种含糊说法。
  • 缺数据一律置灰占位 + 如实说明,不用假数据补齐;降级条写清「缺了什么、影响了什么」。

06与现状的差别(为什么要改)

双层边框嵌套
现状:每票一个卡片,每条预案再套一层带边框 div → 信息密度低。现在:条目之间用虚线分隔,票与票之间用卡片边界。
股票池不可见
现状:看不出这 11 只从哪来、为什么是它们。现在:左栏锚点栏标注来源(持仓 / ★ / 池)与筛选口径。
待办被埋
现状:今日待办在右栏复盘卡底部。现在:复盘整体移到左栏底部,待办紧跟兑现统计。
每天重新选
现状:每天按持仓 ∪ 关注重算,与昨日预案无关。现在:滚动池带记忆,达到预期就留,连续 3 天没到就换新。
