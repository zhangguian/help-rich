## 一、为什么推翻:旧版的 5 个结构性问题

用户反馈「现在的界面不适合金融股市盯盘布局和样式」。逐条对照代码与渲染结果,旧版的问题不在配色而在**结构**:

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | **动作链断裂** —— 选股票在页面最底部,K 线在中部,选完要滚动约 2000px 才看到图 | 旧首页 `page.tsx` 页面高 3194px,盯盘列表排在 K 线区之后 |
| 2 | **首屏被低价值内容占据** —— 三张持仓大卡 + 无坐标无标签的迷你柱图占掉上半屏 | 盯盘时第一眼要的是「看哪只股票」,不是「总市值」 |
| 3 | **信息流没有落点** —— 指数散在右上角三张独立小卡,新手速看(小白核心)被塞进右下角小卡片 | `AnalysisPanel.tsx` 的 `BeginnersGuide` 挂在分析面板尾部 |
| 4 | **视觉语汇是消费级 SaaS** —— 浅蓝渐变画布 + 24px 圆角 + 毛玻璃 + 卡片墙 | `tokens.css` 的 `--glass-radius: 24px`、`globals.css` 的 `liquid-glass` |
| 5 | **导航占了 200px 却只是 emoji** | `NavRail.tsx` 的 `GROUPS` 全部用 emoji 图标 |

### 一个关键的历史教训

`tokens.css` 顶部记着:

> v0.7 曾改为深色投研终端,实测每页内容只占上半屏、下半屏纯黑虚空,空旷感比浅色更刺眼,故回退到 v0.5 视觉底座。

**上一版深色终端失败的原因不是深色,是「卡片墙 + 上下堆叠」的布局撑不满视口。**
本次设计的关键命题因此是:**用满屏工作台布局消灭虚空,而不是靠堆更多卡片。**

## 二、设计方向:「深海交易台」

避开 AI 设计的三种默认套路(暖奶油+衬线 / 近黑+酸绿 / 报纸细线),也**不再回到**旧的 Azure Workbench 浅色毛玻璃。

- **深靛墨底** `#070B12`(不是纯黑,避免死板)
- **红涨绿跌** 用终端级亮色 `#F6465D` / `#0ECB81`(深底上比旧版的 `#e11d48`/`#16a34a` 更跳)
- **青色 `#22D3EE`** 只用于选中态与焦点,**琥珀 `#F5A524`** 只用于预警 —— 行情色与界面强调色严格分离
- **高密度**:小字号、紧行高、等宽数字(`tabular-nums`)纵向对齐
- **浅色版不是「回到旧版」**,而是纸面终端:白底、细线、无投影、无毛玻璃

## 三、布局:满屏三栏工作台

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 买股工具室 │ 自选 关注 持仓  上证 3735.37 +0.12%  深证 …  创业板 …        │ 46px
├──────────────────────────────────────────────────────────────────────────┤
│ 全A 5568只 涨3777 跌1667 涨停59 跌停10 成交1.47万亿                      │ 44px
│ ▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░▓▓▓▓▓▓▓▓  ← 市场宽度色带(签名元素)          │
├────┬────────────────┬──────────────────────────────┬────────────────────┤
│ 48 │ 258px          │ 1fr                          │ 304px              │
│ 图 │ 自选/持仓列表   │ 标的 header + K线(主角)      │ 持仓概览           │
│ 标 │ 43 只,紧凑行   │ + 关键价位 4 卡              │ AI 解读            │
│ 轨 │ 持仓「持」标记  │                              │ 新手速看 5 步      │
│    │ 特别关注「★」  │                              │ 领涨/领跌 + 量能   │
└────┴────────────────┴──────────────────────────────┴────────────────────┘
```

- 旧版 200px emoji 侧栏 → **48px 图标轨**
- 持仓大卡 + 迷你柱图 → 右栏顶部**一行三段**紧凑数字(总市值 / 浮盈 / 今日盈亏)
- K 线从「页面中下部的一小块」→ **中栏绝对主角**
- 新手速看从「右下角小卡片」→ **右栏固定位置**

### 顶栏三个视角(自选 / 关注 / 持仓)

顶栏最左的页签是**视角切换**,只改左栏列表的内容,不动中栏与右栏:

| 视角 | 左栏标题 | 行内标记 | 说明 |
| --- | --- | --- | --- |
| 自选 | 盯盘 (44) | 持仓行挂「持」 | 自选表 ∪ 持仓(持仓未加自选的自动并入) |
| ★ 关注 | 关注 (N) | 「持」 | 只看特别关注 |
| **持仓** | **持仓 (5)** | **浮盈比例 %**(红涨绿跌) | 只看持仓;「持」徽标在全持仓列表里没有信息量,换成精确数字 |

> 持仓视角刻意**不显示「＋添加自选」**:加进来的票不在持仓里,点了会让人以为没生效。
> 顺带把「浮亏红点」也收掉 —— 同一行里已经有精确的浮亏比例,两种颜色表达同一件事会打架;
> 琥珀色的「集中度过高」预警保留(那是另一件事)。

### 响应式(已落码,实测值有调整)

| 宽度 | 行为 |
| --- | --- |
| ≥1280px | 三栏 `252px / 1fr / 304px` |
| 1024–1280px | 三栏收窄为 `236px / 1fr / 268px`(操作按钮只留图标) |
| <1024px | 单栏纵向堆叠:行情列表(38vh)→ 图表舞台 → 决策栏,整页滚动 |

**与初稿的差异(实测后改)**:初稿写「<1040px 时决策栏移到底部横排」。
实测发现**做不到**:决策栏是 `auto` 高度行,内容(持仓概览 + AI + 新手速看 + 领涨领跌 + 量能 + 问一问)
比视口高得多,`auto` 行会吃光空间、把 `1fr` 行压成 0 高度 —— 结果是**列表和图表整栏消失**
(截图确认:1024px 下只剩决策栏)。所以改成「宁可把三栏收窄,也不换行」,
窄于 1024px 才整体堆叠。

### 签名元素:市场宽度色带

把 5568 只股票的涨跌分布做成一条 9 段色带(绿=跌在左 / 红=涨在右,A 股红涨绿跌),
宽度按各档占比,两端标注涨停/跌停。

它回答一个旧版完全没回答的问题:**「今天是普涨,还是只有少数票在涨?」**
当前真实数据:涨 3777 / 跌 1667,`1~5%` 档 2347 只占 42%,涨停 59 / 跌停 10。

### 落码过程中修掉的 4 个真实缺陷

1. **`.panel` 从未定义** —— `Card.tsx` 的默认 variant 引用 `.panel`,但整个前端搜不到该类,
   于是所有 `Card` / `GlassCard` 渲染成无背景无边框的裸 div。已在 `globals.css` 补定义。
2. **`snakeToCamel` 漏转数字段名** —— 后端返回 `up_5_10`,通用规则 `/_([a-z])/g` 只吃「下划线+字母」,
   于是运行时键是 `up_5_10`,而 `types.ts` 声明的是 `up5_10` → **市场宽度色带 6 个档位全部 `undefined`**,
   大盘页「A 股涨跌分布」同样静默失效。已加窄口径规则 `^([a-z]+)_(\d+)_(\d+)$ → $1$2_$3`。
3. **NavRail 折叠逻辑被断点覆盖** —— 断点监听在宽屏时强制展开,覆盖了「默认收起 + 用户偏好」。
   已改为「只收不放 + 手动切换后不再被断点干预」。
4. **1024px 布局塌陷** —— 见上文响应式说明。

**护栏**:
- 行情色(`up`/`down`)只用于价格与图表语境,不得当语义色用(现有 `tokens.css` 已有此约定,继续遵守)
- 不引入新 webfont
- 深浅两套主题都必须过 `prefers-reduced-motion` 与可见焦点态

## 六、收尾补丁:消灭冷启动虚空(2026-10-21 追加)

初版落码后冷启动实拍发现:**首屏没有选中标的时,中栏是一大块
「选择股票后显示 K 线图」的空态** —— 这恰恰是 v0.7 被否掉的「下半屏纯黑虚空」形态,
只是换了张皮。v0.8 的命题是「用满屏工作台消灭虚空」,那它自己也必须消灭。

### 改法(`src/app/(app)/page.tsx`)

| 环节 | 做法 |
| --- | --- |
| 记忆 | 选中股票时写入 `localStorage['rich-last-selected']` |
| 恢复 | 挂载后自选加载完 → 优先恢复上次盯的票(仍需在自选里,被删则不恢复) |
| 兜底 | 没有历史记录 → 自动选中**列表首行**(排序规则与 `WatchList` 完全一致) |
| 一次性 | 用 `restoredRef` 兜住,自动刷新重拉数据时不会改掉用户当前选股 |
| 排序对齐 | 按涨跌幅排序时必须等报价到位,否则「首行」算错(报价是批量一次回来的) |
| 文案 | 区分「正在加载」与「自选确实为空」,不再在加载途中误报「自选列表为空」 |

### 实测

| 场景 | 结果 |
| --- | --- |
| 首次访问(无 localStorage) | 自动选中列表首行 `003033.SZ`,并拉取其 quote / kline(网络面板可见 `GET /api/quotes/003033.SZ`) |
| 选中 `002185.SZ` 后刷新 | 恢复到华天科技(网络面板可见 `GET /api/quotes/002185.SZ` + kline),**不是**列表首行 |
| 1440px 宽屏 | 同样自动恢复,三栏无虚空 |
| 加载途中 | 显示「正在加载自选与持仓…」/「正在加载行情…」 |
| `npm run typecheck` / `npm run build` | 通过(27 路由) |
