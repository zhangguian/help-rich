## 一、盘中复盘抽屉（盯盘页）

### 1.1 它解决什么

盘中复盘的调度**本来就有**（`workflow_scheduler` 的 `intraday_am` / `intraday_pm` 窗口），
但产出只挂在 `/brief` 那个独立页上 —— **盯盘页一个入口都没有**。
用户的主战场是盯盘页，复盘却要专门切个页面去看，等于没有。

所以本轮把入口放进**盯盘页顶栏**，点开是右侧抽屉。

### 1.2 顶栏胶囊的三种状态

| 状态 | 显示 | 判定 |
| --- | --- | --- |
| 已产出 | `盘中复盘 · 11:30 已出` | `schedule.producedSlots` 非空（青点 = 已就绪） |
| 未产出 | `盘中复盘 · 11:30` | 取下一档（灰点），tooltip 给出倒计时 |
| 非交易日 | `今天不是交易日` | `schedule.isTradingDay === false` |

胶囊与抽屉**共用一份数据**（`useIntradayStore`）——不是为了省一次请求，
而是为了避免「胶囊说已出、面板说还没」这种自相矛盾。

### 1.3 两种口径，必须标清楚

抽屉里同时出现两套东西，**混着看会得出错误结论**，所以每块都带口径标签：

| 块 | 口径 | 标签 |
| --- | --- | --- |
| 市场意见 | **盘前四维度推断**，不是盘中重算 | `盘前四维度推断 · 非盘中重算` |
| 操作建议 | 现价 vs 触发价 的比对结果 | `按现价 vs 触发价` |

「操作建议」的动作状态是**四态**，不是阶段 9 的兑现五态：

| 状态 | 含义 | 语义色 |
| --- | --- | --- |
| 已到价待执行 | 现价已越过触发价，可以动手 | 琥珀（实心）= 预警 |
| 未到价 | 还没到触发价，继续等 | 中性 |
| 数据不足 | 缺报价或缺触发价，判不了 | 琥珀（虚线）= 降级 |
| 不适用 | 纪律类（别动/解套路径），不产生价格动作 | 最弱中性 |

**刻意不判「已执行」「已过价」**：那需要当日流水上下文，是阶段 9 兑现模块的职责。
这里判了会与它双写、两个模块说两套话。

### 1.4 空态

| 场景 | 显示 |
| --- | --- |
| 今天还没到档 | `下一次盘中复盘 11:30，还有 N 分钟` |
| 今天不是交易日 | `今天不是交易日` + 日历判定说明 |
| 取数失败（非 404） | 单独报错，**不谎报成「还没生成」** |

最后一条是刻意区分的：404 = 「还没生成」（正常业务语义），500/网络错 = 「取数失败」。
两者混在一起报，用户会以为「再等等就好了」。

### 1.5 每日使用流程（一个必须知道的前提）

盘中复盘的「逐票预案」来自**当日作战计划**（阶段 9），所以：

```text
早上 → 在 /plan 页生成今日作战计划（POST /api/battle-plan/generate，幂等）
     ↓
11:30 / 14:00 → 调度器自动跑盘中复盘 → 盯盘页胶囊变「已出」→ 点开抽屉
```

**当日没有作战计划时，盘中复盘会「响亮失败」**（422「今日作战计划还没生成」），
而不是产出一份缺预案的半成品建议 —— 这是刻意的：宁可不出，也不给一份看着完整、
其实少了「明天怎么办」的复盘。

> 2026-10-23 实测：主库里当日计划缺失时确实跑不出复盘；先生成后
> `plan_date=2026-10-23 / target_date=2026-10-26 / 偏空 / 4 维 / 36 条预案`，
> 11:30 档位即可正常产出。

## 二、全局悬浮球助手

### 2.1 挂载位置与「全局」的含义

挂在 **`AppShell`**（全站可见，任何页面都能唤起），Provider 也在这里。

「全局」有两层含义：

1. **入口全局** —— 不绑定某一只票，任何页面都能问；
2. **上下文全局** —— 自动带上「当前选中的那只票」。

第二层是重点：盯盘页把 `activeCode` 报给 Provider
（`useAssistant().setSelectedStock(code, name)`），
助手在任何页面都拿得到你现在盯的是哪只。

### 2.2 事实包：LLM 唯一允许的数字来源

后端 `app/services/assistant_service.py` 把这些拼成一份事实包：

- 当前选中票（现价 / 涨跌幅 / 持仓成本 / 浮盈）
- 持仓列表
- ★ 关注清单
- 今日作战计划（倾向 / 四维 / 关键位 / 逐票预案）
- 今日盘中复盘（市场意见 + 到价动作）
- 指数快照

**项目铁律「LLM 只翻译不计算」在这里是硬约束**：
作战计划的倾向、四维、关键位、盘中复盘的到价动作，**都是规则层算好的结论**，
助手只负责原样搬运；system prompt 明确要求
「所有数字都必须来自事实包；事实包里没有的，就说没有，禁止编造」。

### 2.3 降级纪律

事实包**每一段独立取数、独立兜底**。某一段挂了：

- 该段标进 `unavailable`（助手因此会直说「持仓数据取不到」）
- 其余段落照常工作
- **绝不整体崩掉什么都不说**

宁可少说，不可瞎说。

### 2.4 表情状态机

32 张设计稿表情落在 `frontend/public/assistant/expressions/`（约 110KB，**不进 JS bundle**）。

> **踩过的坑**：设计稿里的 `<svg>` 是内联片段、**没有 `xmlns`**。
> 内联在 HTML 里不需要命名空间，但抽成独立 `.svg` 后浏览器按图片通道加载时
> 要求根元素在 SVG 命名空间内 —— 否则 46 张图**全挂**（`naturalWidth=0` + error 事件）。
> 补 `xmlns` 后正常。**新抽 SVG 资产时必须先在浏览器里验一张。**

动效范围是**静态帧 + 切换过渡**（CSS 淡入 + 轻微缩放 180ms）——
设计稿里的眨眼轮换 / 彩带自旋 / 呼吸起伏属于原交互 demo 的 JS 行为，附件无脚本，不实现。

| 状态 | 表情 |
| --- | --- |
| idle / loading_history | 待机放空 / 加载苏醒 |
| received → searching → thinking | 接收任务 → 检索资料 → 思考中 |
| speaking / done / error | 输出回复 / 任务完成 / 出错 |
| stopped / unavailable / sleeping | 停止终止 / 拒绝受限 / 睡眠 |

### 2.5 对话历史隔离

存在 IndexedDB 的 `__assistant__` key 下，与个股问答（按 stockCode 分桶）**互不串味**。

落库时用**局部变量累积**回答文本，不用 React state ——
流结束时 `setState` 可能还没提交，那时读 state 会丢掉最后一截。

### 2.6 SSE 契约

`POST /api/assistant/chat/stream`

```
data: {"text": "增量"}
data: {"error": "错误"}
data: {"done": true}
```

**LLM 未配置 → 流开始前 503**：流一旦开始就改不了状态码，只能在流里发 error 事件，
所以前置校验必须在开流前做完。前端据此把表情切成 `unavailable`（不可用）而不是 `error`（出错）。

### 2.7 数字保真：价格要**逐字**引用，不是「原样」

> 这是端到端实测抓到的（见 §六）：prompt 里写了「所有数字必须原样取自事实包」，
> 但 LLM 依然把中国长城的止损价 **`11.625` 四舍五入成了 `11.62`**。
> 「原样」在模型眼里约等于「意思一样」——**止损价差 0.005 也算改判**。

修法（`assistant_service.py` 的 `SYSTEM_PROMPT` 第 6 条 + `build_user_prompt` 复述）：

```
6. **价格逐字引用**:事实包里写 `11.625` 就写 `11.625`,**不要四舍五入**成 `11.62`,
   也不要补零或截断小数位。触发价 / 止损价 / 现价一律如此 —— 改一个数字就是改判。
```

**规则**：`LLM 只翻译不计算`不只是「不许自己算」，还包括**不许把算好的数改精度**。
凡是**会改变结论的数字**（触发价、止损位、支撑压力位），都要在 prompt 里点名要求逐字引用，
并用测试锁住（`test_system_prompt_requires_verbatim_prices`）。

改完复测：同一问题重跑，止损价回到 **`11.625`**。

## 三、性能约束（这条是验收项，不是建议）

| 项 | 约束 | 做法 |
| --- | --- | --- |
| 悬浮球 idle | 无 long task | 纯 CSS + `<img>`，**不用 framer-motion**（常驻 motion 组件带动画运行时开销） |
| 悬浮球切换表情 | 不掉帧 | CSS 过渡，不触发 React 重渲染风暴 |
| 抽屉打开 | 不阻塞主线程 | 内容按需取数，打开时只拉当前档位 |

## 四、语义色纪律

| 用途 | 色 | 说明 |
| --- | --- | --- |
| 涨 / 看多 / 买 / 支撑 | 红 `#f6465d` | 项目铁律：红=买 |
| 跌 / 看空 / 卖 / 压力 | 绿 `#0eeb81` | 绿=卖 |
| 预警 / 失效 / 降级 | 琥珀 `#f5a524` | 已到价待执行、数据不足 |
| 选中 / 焦点 | 青 `#22d3ee` | 只给「当前选中」用（如已产出的档位胶囊） |

> 注意：Tailwind 的 `text-down` 实际渲染为 `#0eeb81`（`--down-rgb: 14 235 129`），
> 而 `tokens.css` 里的 `--status-down: #0ecb81` 是个**没人用的遗留变量**。
> 写新样式时以 Tailwind 工具类为准，别直接引用 `--status-down`。

## 五、顺带修掉的两个既有 bug

1. **`fetchMarketHeader` 注释与实现不符** —— 注释写着「拆开让指数先出」，代码里却还是
   `Promise.all`，被 2.5s 的 `/market/sentiment` 拖着整个大盘速览。
2. **Service Worker 缓存了 Next.js 的 RSC 载荷** —— 「静态资源缓存优先」把 `?_rsc=`
   请求也吃了，发版后老用户点站内链接直接白屏
   （`Cannot read properties of undefined (reading 'call')`）。
   已把 RSC 请求单独放行走网络（见 `frontend/public/sw.js` 的 `isRscRequest`）。

## 六、端到端自检（不打桩）

Plan 的验收要求：「交易日判定 → 盘中复盘 → 调度触发 → 悬浮球 SSE」这条链
必须有**不打桩的端到端自检**，且 **SSE 必须实际收到 `data:` 增量**，不能只看 200。

「不打桩」= 全程真实数据源：交易日历真源是上证指数真实日 K、作战计划取隔离库真实记录、
行情走真实接口、异动扫描跑真实市场扫描。**唯一被拦下的是推送的最后一步外部副作用**
（真发消息不可撤回）—— 脚本先确认 `notify.enabled_channels()` 为空，
为空则 `send_to_enabled` 自动 no-op；**将来若配了真渠道，脚本直接中止而不是偷偷外发**。

### 6.2 悬浮球 SSE 自检（`backend/.pytest_tmp/e2e_assistant_sse.py`）

对着真机后端发真实请求，统计 `data:` 帧：

### 6.3 语义色目视核对（不靠肉眼，取 computed style）

Plan 的验收写的是「目视核对」—— 但**肉眼会看错**（比如「倾向：偏空」在深色底上
一眼看上去像红色）。所以核对脚本直接读 `getComputedStyle().color`，
与设计令牌**逐值比对**（`backend/.pytest_tmp/tb_semantic_colors.js`，9/9 全绿）：

| 元素 | 实测色 | 令牌 | 判定 |
| --- | --- | --- | --- |
| 倾向：偏空 | `rgb(14, 235, 129)` | `down` 绿 | ✅ 看空=绿 |
| 支撑 3649.86 | `rgb(246, 70, 93)` | `up` 红 | ✅ |
| 压力 3714.48 / 3813.14 | `rgb(14, 235, 129)` | `down` 绿 | ✅ |
| 徽章「已到价待执行」 | `rgb(245, 165, 36)` / 底 `rgba(245,165,36,.14)` | `warn` 琥珀 | ✅ 预警=琥珀 |
| 徽章「未到价」 | `rgb(143, 160, 184)` / 底 `rgb(24,33,47)` | 中性 | ✅ 既不是红也不是绿 |
| 差额 `-0.90%` | `rgb(14, 235, 129)` | `down` 绿 | ✅ 跌=绿 |
| 差额 `+2.17%` | `rgb(246, 70, 93)` | `up` 红 | ✅ 涨=红 |

**写法要求**：这类断言要**从 DOM 取色值**，不要从截图里目视判断 ——
「目视核对」是验收意图，不是验收手段。
