# GB-001: 投资评审报告(买股工具室系统)

> **目的**:站在资深投顾/证券顶级经济学家的视角,系统评估"买股工具室"现有实现,识别投资逻辑层的硬伤,排出修复优先级。本报告不写代码,只做"问题清单 + 修复方案"。

## 状态
已采纳(2026-08-04,P0 评审)

## 评审方法

- **对象**:后端 `ta_service` / `cost_engine` / `scorer` / `signal_winrate` / `overview_service` / 数据源 + 前端 + 产品文档 `project-book` / `product-requirements`
- **方式**:代码逐文件读取 + 文档对照,投顾/量化经济学视角
- **结论**:工程韧性扎实(双源降级/Decimal 精度/SSE 降级/AI 不阻塞/降级不报错),**投资逻辑面存在 5 处硬伤,决定"工具是否真帮你变少亏"**——这正是立项时诊断的"反馈环断裂"没有被根除,只是换了一个反馈环(打分)但没闭环(分数没被验证)。

## 问题清单

### IR-1 ⭐P0  大盘环境评分维度已失效

- **位置**:`backend/app/services/diagnose_service.py:147`
  ```python
  market_ctx = {"index_change_pct": 0.0, "sector_rank": None}
  ```
- **缺陷**:20 权重维度永远给"中性 10 分",实际评分满分只有 80。系统无法惩罚"逆势追涨"行为——而这恰是北极星指标(非理性交易占比下降 30%)想约束的核心行为。
- **修复**:评分时拉取当日大盘涨跌幅(上证/沪深300 选其一,默认上证),失败降级 0.0 维持中性。`scorer.py:131-147` 逻辑无需改动,只改 market_ctx 构造。
- **验证**:pytest 新增三档映射用例(顺势20/中性10/逆势0)。

### IR-2 ⭐P0  评分规则与产品核心卖点「做 T」直接冲突

- **位置**:`backend/app/core/scorer.py:97-128`(`_interval_score`)
- **冲突**:`product-requirements.md` 场景 B 的最高频诉求就是日内做 T(高抛低吸),但"操作间隔"维度 <3 天扣 10 分、密集操作更被视为"频繁交易"。系统一边鼓励做 T,一边给做 T 的用户打低分。
- **修复**:`scorer.py` 加 `_is_round_trip()` 识别——同日同股票买卖且净持仓变化 ≤ 阈值(例如 30%)→ 操作间隔维度豁免或替换为"T 价差合理性"评分。
- **验证**:pytest 新增做 T 场景用例(高分入场→低分出场对/错)。

### IR-3 ⭐P1  评分 → 结果 反馈环仍然断裂

- **位置**:`backend/app/models/orm.py` `trade_scores` 表只存当时分数,无样本外验证
- **缺陷**:高分买入是否真优于低分买入无从验证;`project-book` 第九章许诺的北极星指标"非理性交易占比下降 30%"没有任何落地测量。立项时诊断的"反馈环断裂"——做了不知道结果、错了不知道为什么错——被诊断机制替代,但机制本身未闭环。
- **修复**:
  1. 迁移让 `trade_scores` 加 `scored_at`(如已有 created_at 则复用)
  2. 新服务 `score_calibration.py` 周期回检:对每笔评分,20 日后回拉行情计算 `(close_20d / close_trade_day - 1)`,按分数段(<60/60-80/≥80)聚合平均收益与胜率
  3. 风险报告页加"评分校准"区块,展示"评分可信度"提示用户
- **验证**:pytest + tsc + 手动验证校准表生成。

### IR-4 ⭐P1  成本引擎完全不考虑交易费用

- **位置**:`backend/app/core/cost_engine.py` 整文件无任何费用模型
- **危害**:佣金(万2.5~千3)、印花税(卖出 0.05%)、过户费(沪深 0.001%)被忽略。10~100 万账户一年摩擦成本动辄 1~3%;做 T 高频让"21 档盈亏表"和"年度已实现盈亏"**系统性高估真实收益**,胜率统计因此失真。成本引擎虽然是项目 MVP 的"主菜",但产出的"已实现盈亏"数字本身不可信。
- **修复**:
  1. `cost_engine.py` 增加费率参数(佣金率、印花税率、过户费率、最低佣金)
  2. **设置页加"费用参数"开关,默认关闭;开启后双口径显示**(含费 / 不含费),不改变现有用户已熟悉的数字
  3. `calculate_after_transaction` 返回 `realized_pnl_gross` + `realized_pnl_net`
  4. 计算器(21 档)、年度账单、评分展示同时输出两个口径
- **验证**:pytest 费用用例(净/毛两套数字、印花税自动按买卖方向)。

### IR-5 ⭐P1  收益统计口径被做 T 撕裂

- **位置**:`backend/app/services/annual_report_service.py:85`
  ```python
  win_rate = len(profit_list) / n if n > 0 else 0.0
  ```
- **缺陷**:胜率 = 盈利笔数 / 总笔数。做 T 频繁交易会产生大量"小赢一笔",让胜率虚高、样本膨胀;只看笔数不看"持仓周期内收益率"与"时间加权收益率"。
- **修复**:
  1. 胜率按**平仓周期**(一次建仓→彻底清仓)聚合
  2. 增设"T 净贡献"指标 — "本年累计已实现−若不做 T 的(价差)"
  3. 展示时间加权(modified Dietz)收益率,避免笔数误差
- **验证**:pytest 构造混合交易样本(做 T + 趋势持仓),验证胜率与净贡献口径。

### IR-6 P1  主力资金流是估算值,被当真实资金行为

- **位置**:`backend/app/services/market_overview_service.py:300-336` `fetch_main_fund_flow`
- **缺陷**:用 `成交额 × sign(涨幅) × (1 + |涨幅|/10)` 拼出"主力净流入"近似值,前端却把它画成资金行为;新浪 `MoneyFlow.ssl_bkzj` 真实资金接口虽已被复用做板块资金(`sina.py:103-125`),个股资金流 `MoneyFlow.ssl_bkzj_ssggzj` 实际可拿但未接入。
- **修复**:
  1. 短期:前端 camp 卡片 + 数字左上角加"估算值"标注,数据源链指明
  2. 中期:接入 `MoneyFlow.ssl_bkzj_ssggzj` 真实接口,失败时降级到估算并加标签
- **验证**:手动 + 前端文案 + lookup 验证接口可拉。
