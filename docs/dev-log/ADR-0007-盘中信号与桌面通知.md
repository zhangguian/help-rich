# ADR-0007: 盘中持仓信号走「后端判定 + 后端直发 Windows 桌面通知」

## 状态
已采纳(2026-10-29)

## 背景

需求:对**持仓股**在盘中出现的四类事件,弹 **Windows 原生桌面通知** —— 浏览器关着也能收到:

1. 急速拉升 / 急速下跌
2. 涨幅突破 / 跌幅突破
3. 预测做 T 点(卖出 T 仓 / 买回)
4. 预测买点

既有能力盘点(实施前的代码事实):

| 已有 | 缺什么 |
|---|---|
| `services/quote_poller.py`:盘中 2s 一帧,广播 `quote_update` | 没有"速度/斜率"信号 |
| `services/decision_service.py`:`t_plan` / `grid_plan` 的**数值**触发价 | 没有"到价"信号 |
| `modules/notify/`:5 个渠道 + 限流 + 加密配置 | **没有桌面渠道** |
| `modules/alert/`:用户手写条件树 + 60s 调度 | 与本需求是两条线(不动它) |

关键约束(决定了方案形态):

- **浏览器关掉也要能收到** → 前端 `new Notification` 不够,必须**后端直发**。
- **判定口径不能有两套** → 决策卡说 T 卖点 12.50、信号弹 12.20,用户会不认。
- **零新依赖** → `backend/.venv` 里没有 `winotify` / `win11toast` / `plyer` / `winsdk`,
  `BurntToast` 也没装。

## 一、决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 桌面通知形态 | **后端 Windows 原生通知**(PowerShell + WinRT Toast,失败降级托盘气泡) | 浏览器关着也能收到;零新 pip 依赖 |
| 判定落点 | 新建 `app/modules/signal/`,判定层纯函数 | 与用户手写规则的 `alert` 域分开;判定零 IO 可单测 |
| 判定口径 | **复用决策引擎**的 `t_plan` / `grid_plan` / `actions` 数值价位 | 与决策卡 100% 同源,不重算价位 |
| 阈值 | 固定默认值 + 设置页可改 | 默认:急速 60s 内 ±1.5%;突破相对昨收 ±5% |
| 范围 | **只限持仓股**(`shares > 0`,每次现取) | 用户原话「我期望持仓股」 |
| 桌面 Toast 由谁发 | **后端**;前端不再调 `new Notification` | 避免与后端重复弹;浏览器通道在止损里已用过 |

### 1.1 决策装配下沉(Phase 0)

`modules/signal/` 需要复用决策装配,但架构守卫禁止 modules import `app.api.*`
(`tests/test_architecture_boundaries.py::test_modules_do_not_import_legacy_layered_api`)。

因此把 `app/api/stock.py::_compute_decision` 的装配逻辑**下沉**到
`app/services/decision_runtime.py::build_decision_payload`,api 层改为委托。

- `DecisionDeps` 做**依赖注入**:api 层构造 deps 时传入自身模块内的名字
  (`fetch_klines` / `get_position` / `get_market_context` / `load_decision_extras` / `build_decision`),
  既有测试的 patch 点(`patch("app.api.stock.fetch_klines")` 等 6 处)**保持生效,无需改写**。
- `include_env=False` 时不聚合市场环境(省 4~5 次外部 HTTP);`judge_t_plan` / `judge_grid_plan`
  **都不读 env** → 触发价位口径与决策卡完全一致。

### 1.2 检测分层

| 层 | 信号 | 数据源 | 判定频率 | 成本 |
|---|---|---|---|---|
| **L1 快信号** | 急速拉升/下跌 | 2s 帧的滚动窗口 | 每帧 | 纯内存,零 IO |
| **L1 快信号** | 涨幅/跌幅突破 | 现价 + 昨收 | 每帧 | 纯内存,零 IO |
| **L2 慢信号** | 做 T 点、买点 | 决策引擎的**数值**触发价 | 触发价 60s 重算;现价每帧比对 | 60s 一轮重算(11 票并发 ~1~3s),比对零 IO |

**为什么慢信号也能 2s 级响应**:`t_plan` / `grid_plan` 的触发价是**日线派生**(分位带 + 波动区间 +
均线/通道),盘中几乎不变 → 算一次缓存住,盘中只比较现价。

**帧从哪来**:复用 `quote_poller` 已广播的 `quote_update` 事件(通过 `event_bus.subscribe_callback`),
**不额外打行情源** —— 盯盘与信号共用同一批帧。

### 1.3 去重

- **到价类**(`t_sell_point` / `t_buyback_point` / `grid_sell_point` / `buy_point`):
  指纹 = `kind + 代码 + 价位分桶(0.01 元)`,落 `intraday_signal_trigger` 表。
  同价位**当日只提醒一次**,且**跨后端重启**也成立
  (`modules/notify/dedupe.py` 的限流器是纯内存的,重启即清零 —— 见 §三 R4)。
- **斜率/突破类**:靠限流器的**冷却窗口 + 单日上限**(默认 600s / 5 次)。
  不用价位去重 —— 每次拉升的价位都不同,按价位去重会把后续信号全吃掉。

## 二、实现要点

### 2.1 桌面通知通道(`modules/notify/desktop_toast.py`)

**路径**:后端 → `powershell.exe` → WinRT `ToastNotificationManager` → Windows 通知中心。

**踩到的两个硬坑(都已实测并写进代码注释)**:

1. **`The process has no package identity`(0x80073D54)**
   非打包应用直接调 `CreateToastNotifier(AUMID)` 会抛这个错(**借系统 AUMID 也一样抛**)。
   解法:先调 `SetCurrentProcessExplicitAppUserModelID(AUMID)` 给当前进程显式身份,
   再 `CreateToastNotifier(同一个 AUMID)`。实测四组 AUMID(含无快捷方式的自定义 AUMID)全部 SHOW_OK,
   **不需要往开始菜单写任何东西**。
   注意该 API **每进程只能调一次** → 每个 AUMID 候选各起一个 powershell 进程。

2. **`Add-Type` 要写编译临时文件**
   上面那个 P/Invoke 靠 `Add-Type` 现场编译 C#,中间产物写在 `%TEMP%`。
   `%TEMP%` 不可写时 `Add-Type` 报 `UnauthorizedAccessException` → 类型没加载 → 身份没设上 → 回到坑 1。
   解法:**给子进程显式指定一个它自己能写的临时目录**(候选链:`TEMP`/`TMP` → `tempfile.gettempdir()`
   → 应用自己的目录),并在报错像临时目录问题时换目录重试。

**兜底路径(托盘气泡)**:平台不认 package identity 时(受限环境 / 受限令牌 / 非交互会话),
自动降级到 `System.Windows.Forms.NotifyIcon.ShowBalloonTip` —— **不需要 package identity**,
且只用 `Add-Type -AssemblyName`(纯程序集加载,不编译)→ 不依赖临时目录可写。

**传参纪律**:整段脚本用 `-EncodedCommand`(UTF-16LE base64)交给 powershell.exe,
标题/正文再各自 base64(UTF-8)内嵌 → 中文 / 引号 / 换行 / emoji 都不会被 argv 解析坏。

**外观限制(已知)**:借用系统应用的 AUMID 时,Windows 通知中心里显示的是**被借用应用**的名字/图标
(如「Windows PowerShell」),正文与标题是我们的。要彻底解决需注册自有 AUMID
(写开始菜单快捷方式 + `System.AppUserModel.ID`)—— 需用户同意写开始菜单,本轮未做。

### 2.2 新增表

- `intraday_signal_config`(单行 id=1):阈值 / 四个类型开关 / 渠道 / 冷却 / 日限流。
- `intraday_signal_trigger`:触发流水(含 `fingerprint` → 跨重启去重)。
  前端可查「为什么推了这条 / 为什么没推」(被冷却、发送失败都会留痕)。

### 2.3 API

```
GET   /api/signals/config     → 配置 + 运行时(触发价 + 不适合原因)
PATCH /api/signals/config     → 改配置
GET   /api/signals            → 信号流水
GET   /api/signals/stream     → SSE(signal_snapshot / signal_fired)
POST  /api/signals/test       → 真弹一条桌面通知
```

字面量路径必须注册在参数路径之前(FastAPI 按注册顺序匹配 —— 已踩过 `/quotes/stream` 被 `{code}` 吃掉的坑)。

### 2.4 架构边界

- `modules/signal/` **不 import** `app.api.*`(决策装配走 `app/services/decision_runtime.py`)。
- 跨域只经 `service.py`:取持仓走 `app.modules.portfolio.service.get_all_positions`,
  发通知走 `app.modules.notify.service.notify_service`(**不得** import `notify.base`)。
- `modules/signal/repository.py` 不 import api/services ✓。

## 三、风险与实测结论

| # | 风险 | 结论 / 应对 |
|---|---|---|
| R1 | 借用 AUMID → 通知中心显示为系统应用名 | 已知外观限制;自有 AUMID 需写开始菜单(待用户同意) |
| R2 | PowerShell 每次启动 ~200~400ms | 子进程不阻塞事件循环;通知量低(冷却 + 日限流) |
| R3 | CI 在 Linux → 平台代码不能 import 期执行 | 平台判断收在函数内;单测覆盖非 Windows 分支 |
| R4 | 限流器纯内存 → 重启后同价位可能重弹 | **已解**:指纹落 `intraday_signal_trigger`,按 `notified=True` 过滤 → 跨重启也成立 |
| R5 | 决策/K 线抖动 → 慢信号缺失 | 降级明示(`notes` 里给原文原因);快信号不受影响 |
| R6 | 11 票每 60s 重算撞行情源限流 | `Semaphore(4)` 限并发 + 单票异常隔离 |
| R7 | Toast 在受限进程里被平台拒 | 已加**托盘气泡**兜底,两条路径都失败才报错 |

**实测记录(本机)**:

- `POST /api/notify/channels/desktop/test` → `{"ok":true,"detail":"OK:BALLOON"}`(受限环境下走气泡兜底)。
- 同一台机器上,**非受限**进程(直接由 shell 启动)走 WinRT Toast 路径:
  `SHOW_OK`,且 Windows 通知设置注册表**新增了该 AUMID 键** → 平台确实受理了这次投递。
- 结论:**受限进程(受限令牌 / 沙箱 / 非交互会话)下平台不受理 package identity → 由气泡兜底**;
  普通交互式会话走 Toast。

## 四、验收

- 后端全量 `pytest` 0 failed;`ruff` 本轮涉及文件零新增。
- 判定层边界:样本不足→None;阈值边界含等号;突破迟滞 0.5%;到价 ≥ / ≤ 边界含等号。
- 架构守卫 `test_architecture_boundaries.py` 全绿。
