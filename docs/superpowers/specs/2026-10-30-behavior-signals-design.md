# K 线异动行为标注(四信号)+ 找股模块 — 设计文档

> 日期：2026-10-30
> 状态：设计已批准并实施完毕(v0.15)
> 背景：用户诉求「期望 K 线可以标明一些 K 线异动行为,低吸信号出现,提前发现行情,锁仓信号出现,高抛信号出现」+「按这些信号加一个找股功能模块」
> 口径来源：用户提供的截图是某券商广告产品的**黑盒口径**,**不是**本项目的判定标准 —— 本项目用可解释的纯规则重新定义四类信号

---

## 一、问题定位

### 1.1 现状缺口

| 能力 | 现状 | 缺口 |
|---|---|---|
| K 线信号标注 | `ta_service._signal_series()` | **只标最后一根 K 线**(全部堆在末日)→ 无法标出「某天出现过低吸信号」 |
| 盘中信号推送 | `modules/signal/engine.py` | 是**盘中实时**推送(ADR-0007),与日线形态回溯定位不同,**不混用** |
| 选股 | `modules/screener/` | 按**因子打分**排 Top 20;候选池是**指数成分股**,无「按 K 线行为信号筛」这一维 |

### 1.2 与盘中信号模块的边界（易混点，必须说清）

| | `modules/signal/engine.py` | 本模块 |
|---|---|---|
| 时间尺度 | **盘中实时**(2s 帧滚动窗口) | **日线**、逐日回溯 |
| 产出 | 推送(SSE + 桌面通知)+ 落库流水 | **标注点序列**(给 K 线图)+ 找股命中列表 |
| 触发对象 | 实时行情事件 | 历史某日可观测的形态事实 |

两者**不合并**：合并会破坏 ADR-0007 的推送语义（到价类信号靠指纹去重、靠冷却窗口限流）。

## 三、数据源(实测,2026-10-30)

| 用途 | 接口 | 实测 |
|---|---|---|
| 日 K | `quotes.sina.cn/.../CN_MarketDataService.getKLineData` | ✅ 字段 `day/open/high/low/close/volume`(**无 amount**,成交额需 `volume × close`) |
| **个股历史逐日资金流** | `vip.stock.finance.sina.com.cn/.../MoneyFlow.ssl_qsfx_zjlrqs` | ✅ 逐日 `opendate/changeratio/turnover/netamount/ratioamount/r0_net/r0_ratio/r0x_ratio`;`num=120` 可一次拿 120 日 |
| 全市场资金排行 | `.../MoneyFlow.ssl_bkzj_ssggzj` | ✅ `num=100` 分页;**全量 57 页 / 5700 只 / 14.5s** |
| 全市场快照 | `app/data/market_snapshot.py` | ✅ 5574 只 / 3.4s |
| 候选批量取数 | K线(120)+资金流(120)并发 | ✅ **12 只 0.85s** → 120 只约 7s |

**不引入新数据源、不违反 ADR-0006**(不引入 akshare)。

### 3.1 编码(实测修正)

响应头虽为 `charset=gbk`,但**服务端已把中文转义成 `\uXXXX`** → `resp.json()` 即得正确字符串。
**必须用 `resp.json()`,不要用 `resp.text` 再手动 decode**(那才会乱码)。现有 `market_snapshot.py` 口径一致,新代码跟随。

### 3.2 日期对齐(硬约束)

实测:K 线**升序**、资金流**降序**(`sort=opendate&asc=0`),日期集合相同。

→ **必须按 date 字典对齐,绝不按索引 zip**。索引 zip 会让两者**整体错位一天**,
产生看似合理实则完全错误的信号 —— 这是本需求最危险的静默错误。

**防线**:判定层内部**自行按日期取「前一日」**(不依赖调用方预填 `__prev__`),
正确性收敛在模块内部;单测钉死「资金流缺一天 → 该日不产信号,不与相邻日错位」。

## 四、四类信号规则

全部阈值外置 `core/config.py`(`BEHAVIOR_*` 前缀),便于回测调参。

| 信号 | 触发条件 | 位置 | 颜色 |
|---|---|---|---|
| **主力异动** `main_force_move` | `r0_net` > 0 且 `r0x_ratio` ≥ 65% 且 涨幅 ≥ 2% 且 量比 ≥ 1.5 | aboveBar | `#f59e0b` 琥珀 |
| **低吸信号** `dip_buy` | 主力净额**由负转正** + 下影 ≥ 实体×1.5 + 收盘回踩 MA20(偏离 ≤3%) + 量比 ≤ 1.0 | belowBar | `#22d3ee` 青 |
| **锁仓信号** `lock_position` | 连续 5 日主力净额为正且累计 ≥ 0.5 亿 + 期间振幅 ≤ 8%(横盘)+ 期间均量 ≤ 前 5 日均量×0.9(缩量) | belowBar | `#a78bfa` 紫 |
| **高抛信号** `distribute` | 主力净额**由正转负** + 上影 ≥ 实体×1.5 + 距近 20 日高 ≤ 5% + 量比 ≥ 1.5 | aboveBar | `#f43f5e` 红 |

### 4.0 ⚠️ 阈值是**真机数据调出来的**(不是拍脑袋)

初版主力异动取 `r0x ≥ 50% / 涨幅 ≥ 1% / 量比 ≥ 1.3`。真机跑全市场(5574 只,2026-10-30)
发现:在大盘普涨日它命中了 **908/1121 = 81%** 的命中记录 —— 几乎每只涨得多的票
都成「主力异动」,**等于没筛**。同时 455 条命中里绝大多数贴着阈值(65.1% / 2.01% / 1.502),
真正强势的反而淹没在长尾里。

收紧为 `65% / 2% / 1.5` 后:命中 1121 → **663** 条,其中主力异动 908 → **455** 条,
耗时 54.89s → **13.48s**(少打一半外网请求)。高抛的放量阈值同步从 1.3 提到 1.5
——大盘普跌日同样会大量触发,两个阈值必须对称。

**教训**:「命中」不等于「有区分度」。阈值的验收标准不是"能命中",
而是**「命中集合里能不能排出先后」** —— 后者才需要 §4.3 的强度分级。

### 4.3 强度分级(主力异动)

命中只是第一层,**强度**决定谁排前面。

**四个维度的「过线进度」**:每个维度按 `进度 = (实测值 − 判定线) / (强线 − 判定线)`,
截断到 `[0, 1]`(刚过判定线 = 0,达到强线 = 1)。

| 维度 | 判定线 | 强线 |
|---|---|---|
| 主力净占比 `r0x_ratio` | 65% | 85% |
| 涨跌幅 `change_pct` | 2% | 7% |
| 量比 `volume_ratio` | 1.5 | 3.0 |
| 超大单净额 `r0_net_yi` | 0 | 5 亿 |

- **进度 = 四维均值**(取均值不是取最大:取最大会让「只靠一个维度拔尖」的票
  与「四维均衡」的票并列,失真)。
- **强度系数** = `0.5 + 1.5 × 进度`(范围 0.5 ~ 2.0)。
- **等级**「强 / 一般」由**同一个进度**决定(≥ 0.6 为强)——
  等级与分数**同源**,不会出现「等级写着强、分数却排在一般后面」的自相矛盾。

⚠️ **踩过的坑**:早期版本给「强」的票统一加到上限(2.0),结果同一天所有「强」的
主力异动**分数完全并列**(实测前 5 名全是 170.0),排序形同虚设。
改成连续系数后 Top 12 分数为 147.0 / 146.8 / 141.3 / 134.5 / 131.9 / 128.0 …,
**可辨且无并列**。

实测定档:455 条主力异动中「强」173 条(38%)、一般 282 条 —— 徽标有区分度,
不至于七成都标「强」而失去意义。

### 4.1 设计铁律

1. **缺数据 → 该信号不产出**,绝不编数字。
2. 每条标记**必须带数值依据**(`reason` 写清实测值与阈值)。
3. 只用**当日及之前**的数据 → 可回测、可复现。
4. 文案只陈述**已发生的事实**,**不预测涨跌**(项目红线)。
   「低吸」「高抛」是形态名称,**不是操作建议** —— 词典每条的 `watch` 都写明它「不代表什么」。

### 4.2 序列起点无关性(闭环前提)

「回踩 MA20」「近 20 日高位」「连续 N 日」都依赖滑动窗口,而窗口起点随序列长度变化
(K 线图拉 300 根,找股拉 120 根)。

→ **规定**:判定层固定要求**至少 120 根 K 线**,所有窗口取「当日往前 N 根」的**尾窗**。
→ 同一只票在两处得出**同一批信号** → 保证「找股页看到信号 → 点进个股页在图上找得到」。
→ 单测钉死:同一份数据在 120 根与 300 根输入下,重叠区间的信号结果完全一致。

## 五、后端设计

### 5.1 新增判定层 `app/services/behavior_signal_service.py`

**纯函数、零 IO、零 LLM**(与 `ta_service` / `pool_logic` 同风格)。

- 输出 `BehaviorMarker`:kind / date / date_index / text / position / color / reason / metrics
- `ta_service` **零改动** —— 它已有 `_macd/_kdj/_boll` 等,但 series 只留最后 60 项且
  `_patterns`/`_liar_trap` 是末日语义;行为信号层自算所需均线/量比序列(纯 SMA,代价极低),
  避免影响既有契约与回测基线。

### 5.2 新增资金流层 `app/services/behavior_fund_flow_service.py`

**为什么要有缓存层**:K 线走 `KlineCache`(DB 优先)所以端点很快;资金流若无缓存,
每开一次 K 线图都新增一次外网请求 → **拖慢主流程**。

- 口径与 `fetch_klines` 同构:**DB 优先 → miss 拉真实接口 → 回填落库**;
  收盘后当日数据强制重拉(与 K 线同样的陈旧检测)。
- `align_by_date()` 是对外**唯一**的对齐入口。
- 拉取超时 3s → 超时即降级,**绝不拖慢 K 线主流程**。

### 5.3 K 线端点扩展

`GET /api/kline/{code}/indicators` **追加** `behavior_markers` + `behavior_markers_unavailable`,
既有字段完全不变 → **零回归风险**。

### 5.4 找股模块 `app/modules/behavior_screener/`

```
① 全市场快照(5574)
   │ 主板闸门 + ST 剔除 + 成交额 ≥ 1 亿
   ▼
② 候选粗筛 → Top 120
   ▼
③ 候选逐只并发拉 K线(120) + 资金流(120) → 四信号判定
   ▼
④ 打分(类型权重 × 新鲜度 × 强度 × 100)→ 分组 + 综合排序
```

- 复用 `stock_pool.service.filter_universe()`(同源 universe 口径)。
  **跨域只 import 对方的 `service.py`**(架构边界测试强制)→ 为此在
  `stock_pool/service.py` 导出 `filter_universe` / `UniverseStats`。
- 并发 12;落库 `behavior_signal_run` + `behavior_signal_pick`。

### 5.5 ⚠️ 打分要放大到 100,否则排不出差别

初版打分 `类型权重 × 新鲜度 × 强度` 落在 **1.3 ~ 1.5** —— 全市场几百条命中
挤在同一个小数区间,排序差异**肉眼不可辨**,排序等于随机。

→ 乘 `_SCORE_SCALE = 100.0`,分数落到 **18.9 ~ 147.0**(极差 128.1)。
新鲜度衰减 `0.85^days_ago`(下限 0.3)、类型权重 `BEHAVIOR_SCREENER_KIND_WEIGHTS`
(主力异动 1.0 / 低吸 1.2 / 锁仓 1.1 / 高抛 0.9)保持不变。

## 六、前端设计

### 6.1 ⚠️ marker 合并必须重排序(最高优先级实现细节)

`lightweight-charts@4.2.3` 的 `setMarkers` 文档明确要求:

> "This array should be sorted by time. Several markers with same time are allowed."

`signal_series` 全落在末日、`behavior_markers` 跨历史日期 → 直接 concat 会**无序**
→ 库抛错 → 旧的 `catch {}` **静默吞掉** → **所有标注一起消失**(连原有金叉/形态标注也没了),
且页面**无任何报错提示**。

**做法**:合并 → 按 `time` 升序排序 → `markersRef` 存排序后的数组(命中测试的堆叠偏移依赖顺序)
→ 异常改为 `console.warn`(不再静默)。

### 6.2 ⚠️ 依据文字不能复用 `nowLine`

`SignalExplainCard` 的 `nowLine` 是「**当前这只票**的真实数据」,取**末根 K 线**
(`date/close/pct`)+ 当前指标末值 —— 与「悬停的那个信号发生在哪一天」无关。

本需求的依据文字是**信号发生当日的数值**。

→ 不能混用(会把 10-28 的信号配上 10-30 的现价)。
→ 做法:解释卡**新增独立可选段**「当日依据」,取自 marker 自带的 `reason`;`nowLine` 保持原义。

### 6.3 词典

新增 4 条词条(`主力异动` / `低吸信号` / `锁仓信号` / `高抛信号`),
按现有 `kind/kindLabel/what/soWhat/watch` 四段结构;`resolveSignalTerm` 加前缀回退分支。

### 6.4 找股页

新路由 `/behavior-screener`;NavRail「决策」组新增「找股」。

- 顶部**口径条**:全市场 → 成交额达标 → 逐票算信号 → 命中信号(**各级真实数字**)。
- 顶部**口径说明**:明确写清与「选股」页的区别(否则用户以为两页数据应一致)。
- 按信号类型分组;每条显示信号日、`days_ago`、依据文字、涨跌幅、强度分。
- 点击跳 `/stock/[code]` → 该页 K 线**确实带标注**(闭环)。
- 空态严格区分「**还没跑**」(404)与「**跑了但没命中**」。

### 6.5 ⚠️ 闭环要求个股页有**日 K 图**(真机才发现的断链)

设计稿写「点进个股页 → 该页 K 线确实带标注」,但真机走一遍才发现:
**个股页原本只有分时图**,而四类行为标注是**日线级别**的形态回溯 ——
画在分时图上根本不成立。于是「找股页看到信号 → 点进个股页在图上找得到」
这条闭环实际是**断的**(跳过去了,但落点页没有带标注的 K 线)。

→ 个股页补一张 `KLineChart`(复用盯盘页**同一个**组件,它已合并
`signalSeries` + `behaviorMarkers` 并按 time 排序),不新造图表组件、不新造样式。

顺带修掉一个**既有**布局缺陷:分时图原本被塞进 `h-[320px]` 的 Card,
但 `IntradayChart` 默认 `height=420` → **溢出 150px 压在下一张卡上**
(下方内容被时间轴/成交量标签糊住)。改为卡片按内容撑开 + 图表高度写死。

### 6.6 ⚠️ 前端响应体会被**递归**转成驼峰

axios 响应拦截器(`lib/api.ts` 的 `snakeToCamel`)会把**整棵响应树**的
snake_case 键转成 camelCase。因此前端 API 层的 TS 类型**必须写驼峰** ——
写成 snake_case 时 TS 不会报错(泛型只是断言),但运行期读出来全是 `undefined`。

真机踩到:`BehaviorPoolResponse.universe` 写成 `main_board` / `non_st` /
`after_filters` → 口径条渲染成「主板 只 · 非 ST 只 · 成交额 ≥ 1 亿后剩 只」
(**数字全空**,但对象存在所以整行还在,很容易被当成"接口没数据")。
已改为 `mainBoard` / `nonSt` / `afterFilters`。

### 6.7 ⚠️ 涨跌幅必须取**信号当日**,不是今天

找股页把涨跌幅显示在「信号日 2026-10-30(1 天前)」旁边,它就必须是**那一天**的涨跌幅。

真机发现早期版本用的是全市场快照里的**当日(今天)**涨跌幅 ——
于是同一条记录里「+0.02%」和依据里的「当日涨跌 +10.00%」**互相矛盾**,
用户无从判断哪个说的是信号当天。

→ 取值优先级:① marker 自带的 `metrics.change_pct`(主力异动判定用的实测值,
与依据文字逐字一致);② 从 K 线算(`close[i] / close[i-1] - 1`),其余三类信号
没有资金流涨跌字段时走这条;③ 算不出 → `null`(前端显示 `-`),**不编数字**。

同时删掉 `score_hit` 里那个**从来没被用过的** `change_pct` 入参 ——
留着就是"接口看起来能用、实际没生效"的坑。涨跌是展示信息,不打分。
