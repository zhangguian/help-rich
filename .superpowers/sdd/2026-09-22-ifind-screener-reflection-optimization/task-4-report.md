The KlineCache removal was essential to avoid SQLAlchemy metadata conflict (the untracked `k3f4g5h6i7j8_drop_kline_cache.py` migration drops the `kline_cache` table; if orm.py still declares `KlineCache`, alembic autogenerate sees mismatch). This is correct because the untracked migration is in the `migrations/versions/` directory, so alembic sees it as part of the graph regardless of git status. Both migrations should be committed together (the user is aware of this — `k3f4g5h6i7j8` was already in their working tree before my task).

4. **ORM model uses Mapped/mapped_column style** instead of brief's Column-based style. This matches the existing file style (all other classes in orm.py use `Mapped`/`mapped_column`).
