## 第零章 时机与背景(v1.4 新增)

### 0.1 立项时机

- 2026 Q3,发起人因操作失误持续亏损
- 受限于个人能力,亏损的根本原因是**"不会评估交易"**
- 现有工具(同花顺/东财/雪球)能"显示数据",但不能"诊断交易"
- 关联项目 stock_project-master 已能给出买卖点,但缺执行监督

### 0.2 为什么是现在

- DeepSeek 等国内 LLM 成本下降,使得 AI 诊断成为可能
- 个人项目时间窗口:用户愿意投入 1~2 周开发
- 经验教训:3 次以上"追涨亏损",再不反思会继续亏

### 0.3 不做会怎样

- 不做这个工具,用户会继续凭感觉操作
- 3 个月内大概率再亏损
- "亏损 → 想学 → 没工具 → 继续亏损"恶性循环

## 第一章 项目概述

### 1.1 一句话定义
> 一个本地运行的 Web 工具 + AI 诊断层,**只解决一件事**——让用户在每次交易前后,60 秒内知道"这笔做得对不对、做完后账户变成什么样"。

### 1.2 v1.1 → v1.2 关键变更(PM 评审后)

| # | 项目 | v1.1 原方案 | v1.2 调整 | 理由 |
|---|---|---|---|---|
| 1 | MVP 模块数 | 6 个 | **3 个** | 避免范围蔓延,3~5 天上线 |
| 2 | 隐藏 P0 | 未识别 | **单笔交易诊断前移** | "判断对错"才是深层痛点 |

### 1.3 边界清单(扩展版,v1.4)

#### ❌ 不接券商交易接口
- **原因**:合规风险高,MVP 阶段不必要
- **何时重评估**:v1.0 阶段,如有明确市场需求

#### ⏸ 实时盯盘(WebSocket 推送)
- **原因**:免费数据源延迟 15 分钟,假装实时是欺骗
- **何时重评估**:用户愿意付费购买实时数据时

#### ❌ 多用户系统
- **原因**:个人自用,多用户会引入复杂度
- **何时重评估**:不再作为评估项(永久排除)

#### ⏸ 选股自定义编辑器
- **原因**:MVP 阶段 4 个预设策略已够,自定义复杂度高
- **何时重评估**:v0.3 之后,如有明确需求

#### ❌ SaaS 化 / 云端部署
- **原因**:个人数据敏感性 + 部署成本
- **何时重评估**:产品被验证有商业价值时

#### ❌ 多券商截图识别(v2.0 新增)
- **原因**:OCR 规则单一(只同花顺);适配多券商规则成本 N 倍,超出 MVP 范围
- **何时重评估**:用户切换券商或需要支持其他券商时

#### ❌ OCR 自动适配不同 App(v2.0 新增)
- **原因**:同花顺布局固定,OCR 规则基于此设计
- **何时重评估**:用户明确需求扩展其他 App

#### ✅ Prompt 模板外发(降级路径,v2.0 新增)
- **原因**:不强求 3 Provider 都支持视觉识别;用户可自选外网可识图模型 + 我们的 Prompt + 粘贴 JSON
- **何时重评估**:N/A(永久允许)

#### ❌ 截图上传到云端(v2.0 新增)
- **原因**:隐私红线;图片含持仓金额 = 敏感数据
- **何时重评估**:永不评估(永久禁止)

## 第二章 用户痛点(分层)

### 2.1 表层痛点(用户原话)

| 痛点 | 严重度 |
|---|---|
| 不会选股 | ★★★ |
| 不会看市场 | ★★★ |
| 不会看 K 线 | ★★ |
| 不会看基本面 | ★★ |
| 不会评估一笔交易 / 做 T | ⭐⭐⭐⭐⭐ |

### 2.2 深层痛点(PM 分析)

> 表层痛点的根因是**反馈环断裂**——做了不知道结果,错了不知道为什么错,无法形成"经验积累"。

| 深层痛点 | 对应模块 |
|---|---|
| **不知道每笔交易是否合理**(反馈缺失) | ⭐ 单笔交易诊断(本模块) |
| **不知道加减仓后真实成本是多少**(算不清) | ⭐ 交易成本计算器(本模块) |
| **没有持久化的持仓账本**(数据缺失) | 交易流水录入(本模块) |
| 看不懂 K 线 / 基本面 / 市场 | v0.2+ |

**结论**:**MVP 必须打通"录入 → 计算 → 诊断"完整闭环**,只解决这 3 个深层痛点,即可让用户形成反馈环。

### 2.3 用户一天故事地图(v1.4 新增)

> 跳出"功能视角",从用户真实一天怎么用这个工具的视角看。

#### 盘前(09:00)
- 看昨晚市场速评(v0.2)
- 检查自选股异动(v0.2)
- 决定今天要不要操作

#### 盘后(15:30)
- **用计算器试算加仓** ← MVP 主菜
- 在券商下单(此软件不下单)
- **回来录入交易** ← MVP 入口

#### 睡前(22:00)
- **看当日评分与评语** ← MVP 价值
- 反思:今天是不是又追涨了?
- 看月度复盘(每月一次,v0.3)

#### 设计意义

| 场景 | 频次 | 对应模块 | MVP 优先级 |
|---|---|---|---|
| 早晨场景 | 每日 1 次 | 计算器 | ⭐⭐⭐⭐⭐(用得早) |
| 盘后场景 | 每日 1~3 次 | 流水录入 + 评分 | ⭐⭐⭐⭐⭐(用得多) |
| 睡前场景 | 每日 1 次 | AI 评语 | ⭐⭐⭐⭐⭐(价值高) |
| 周末场景 | 每周 1 次 | 月度复盘 | v0.3 |

**结论**:MVP 三个模块(流水/计算器/诊断)正好对应"盘后"和"睡前"两个高频场景。

## 第四章 详细功能设计

### 4.1 模块一:交易流水录入

#### 4.1.1 数据模型 `transactions` 表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | 主键 |
| stock_code | TEXT | NOT NULL | 股票代码,如 000001 |
| stock_name | TEXT | NULL | 股票名称(可从行情接口补) |
| action | TEXT | NOT NULL CHECK IN (buy, sell) | 交易方向 |
| shares | INTEGER | NOT NULL, > 0 | 交易股数(整百) |
| price | DECIMAL(10,3) | NOT NULL, > 0 | 交易价格,3 位小数 |
| trade_date | DATE | NOT NULL | 交易日期 |
| note | TEXT | NULL | 备注 |
| created_at | DATETIME | DEFAULT now | 录入时间 |

#### 4.1.2 `positions` 聚合视图(由 transactions 计算,不持久化)

```sql
SELECT
  stock_code,
  ANY_VALUE(stock_name) AS stock_name,
  SUM(CASE WHEN action='buy'  THEN  shares ELSE -shares END) AS shares,
  SUM(CASE WHEN action='buy' THEN shares*price ELSE 0 END)
  / NULLIF(SUM(CASE WHEN action='buy' THEN shares ELSE 0 END), 0) AS avg_cost,
  SUM(CASE WHEN action='buy' THEN shares*price ELSE -shares*price END) AS net_cash_flow
FROM transactions
GROUP BY stock_code
HAVING shares > 0;
```

#### 4.1.3 交互要点

- **表单录入**:股票代码自动联想名称(本地缓存 + AkShare)
- **流水列表**:支持修改、删除、按日期/股票筛选
- **持仓概览**:从流水聚合显示,每只票显示股数 / 加权成本 / 浮动盈亏
- **校验**:卖出股数 ≤ 持仓;价格 > 0;股数 > 0

#### 4.1.4 录入后立即触发诊断

```
用户提交交易
  ↓
写入 transactions 表(同步)
  ↓
触发交易诊断(异步,不阻塞)
  ↓
诊断结果通过 WebSocket/SSE 推送到前端
```

### 4.2 模块二:交易成本计算器 ⭐(主菜)

#### 4.2.1 输入

| 参数 | 类型 | 说明 |
|---|---|---|
| stock_code | TEXT | 目标股票 |
| action | enum | `buy` 或 `sell` |
| tx_shares | int | 本次交易股数 |
| tx_price | decimal | 本次交易价格 |

#### 4.2.2 核心算法(加权平均法)

```
买入:
  S' = S₀ + S₁
  T' = T₀ + (S₁ × P₁)
  C' = T' / S'

卖出:
  S' = S₀ - S₁
  C' = C₀                      # 剩余持仓成本不变
  已实现盈亏 = (P₁ - C₀) × S₁
  T' = T₀ - (S₁ × P₁)
```

#### 4.2.3 21 档盈亏表

| 项 | 说明 |
|---|---|
| 档位数 | 21 档(-10% ~ +10%,含 0) |
| 价格精度 | 3 位小数 |
| 计算基准 | **新成本价 C'** |
| 字段 | pct, price, market_value, pnl(金额) |
| 可视化 | 横向条形图,0 轴居中,左红右绿 |

#### 4.2.4 输出结构

```json
{
  "input": {"stock_code": "000001", "action": "buy", "tx_shares": 500, "tx_price": 11.0},
  "before": {"shares": 1000, "cost_price": 10.0, "total_cost": 10000.0},
  "after": {
    "shares": 1500,
    "cost_price": 10.333,
    "total_cost": 15500.0,
    "delta_cost": 0.333,
    "realized_pnl": 0
  },
  "pnl_grid": [
    {"pct": -10, "price": 9.300, "market_value": 13950.0, "pnl": -1550.0},
    {"pct":   0, "price": 10.333, "market_value": 15499.5, "pnl": -0.5},
    {"pct":  10, "price": 11.366, "market_value": 17049.0, "pnl": 1549.0}
  ]
}
```

#### 4.2.5 边界与异常

| 情况 | 行为 |
|---|---|
| 卖出股数 > 持仓 | 422,提示"超过持仓 N 股" |
| 价格 ≤ 0 或股数 ≤ 0 | 422,校验失败 |
| 卖出后股数 = 0 | 新成本 = null,提示"已清仓",盈亏表全 0 |
| 浮点精度 | 全模块 `Decimal`,金额 2 位,价格 3 位 |
| 持仓不存在做买入 | 视为初始建仓,成本价 = 买入价 |

```
┌──────────────────────────────────────────────────────────────┐
```

### 4.3 模块三:单笔交易诊断 ⭐(隐藏 P0)

> **设计目标**:不只是"AI 评语",还要"可量化的分数",让用户一眼知道这笔是否合理。

#### 4.3.1 触发时机

- 用户在交易流水录入页提交一笔交易后
- **异步**触发(不阻塞录入响应)
- 诊断结果通过 SSE 推到前端,展示在"交易流水列表"的对应行

**SSE 实现要点(v1.3 补充)**:
- **单连接**:全局一个 EventSource,按 `trade_id` 过滤
- **数据格式**:`{trade_id, score, breakdown, ai_comment}`
- **断线重连**:浏览器原生 EventSource,3s 自动重连
- **降级**:SSE 失败 → 5s 轮询 `GET /api/diagnose/{trade_id}` 兜底

#### 4.3.2 量化评分(0~100)

**5 个维度,默认权重**:

| 维度 | 满分 | 评分规则 |
|---|---|---|
| **集中度** | 20 | 单只占持仓 < 30% 得满分;30~50% 扣 5;> 50% 扣 20 |
| **价格合理性** | 20 | 买入价相对成本 < 5% 得满分;5~10% 扣 10;> 10% 扣 15(疑似追涨) |
| **操作间隔** | 20 | 距上次同向操作 > 7 天得满分;3~7 天扣 5;< 3 天扣 10(疑似频繁) |
| **市场环境** | 20 | **顺势 20 分 / 中性 10 分 / 逆势 0 分**(与当日大盘方向一致 = 顺势,反向 = 逆势,横盘 = 中性) |
| **板块热度** | 20 | 当日所属板块涨幅前 5 得满分;6~10 得 10;> 10 得 0 |

> 分数为相对参考,非绝对好坏。例如"逆势抄底高分"也可能合理。

#### 4.3.3 AI 评语

**触发条件**:
- 分数 < 60 → 必出评语(指出问题)
- 分数 60~80 → 可选评语(中性提示)
- 分数 > 80 → 不出评语(避免噪音)

**Prompt 模板**:

#### 4.3.6 评分函数实现要点

**额外接收上下文(用于 AI 评语措辞,不影响分数)**:
- `is_in_watchlist: bool` — 该股票是否在自选股中

**联动逻辑**:
- 持仓外的股票发生买入时 → 前端轻提示"是否加入自选股?"(非阻塞)
- 用户点击确认 → 写入 `watchlist` 表(source = diagnosis)
- AI 评语根据 `is_in_watchlist` 调整措辞(见 4.3.3 Prompt)

```python
def score_trade(trade, position_before, recent_trades, market_ctx, is_in_watchlist: bool) -> dict:
    breakdown = {}

    # 1. 集中度(0 数据降级:持仓数 < 3 只时默认 15 分)
    holdings_count = len(all_positions)
    if holdings_count < 3:
        breakdown["集中度"] = 15  # 0 数据降级
    else:
        position_value = trade.shares * trade.price
        total_value = sum_position_value() + position_value
        concentration = position_value / total_value if total_value else 0
        if concentration < 0.30:
            breakdown["集中度"] = 20
        elif concentration < 0.50:
            breakdown["集中度"] = 15
        else:
            breakdown["集中度"] = 0

    # 2. 价格合理性
    if trade.action == "buy" and position_before["shares"] > 0:
        cost_diff_pct = abs(trade.price - position_before["cost_price"]) / position_before["cost_price"]
        if cost_diff_pct < 0.05:
            breakdown["价格合理性"] = 20
        elif cost_diff_pct < 0.10:
            breakdown["价格合理性"] = 10
        else:
            breakdown["价格合理性"] = 5
    else:
        breakdown["价格合理性"] = 15  # 卖出或新建仓默认中等

    # 3. 操作间隔(0 数据降级:历史交易 < 2 笔时默认 15 分)
    recent_count = len(recent_trades)
    if recent_count < 2:
        breakdown["操作间隔"] = 15  # 0 数据降级
    else:
        last_same_dir = find_last_same_action(recent_trades, trade)
        days_since = (trade.trade_date - last_same_dir.trade_date).days if last_same_dir else 999
        if days_since > 7:
            breakdown["操作间隔"] = 20
        elif days_since > 3:
            breakdown["操作间隔"] = 15
        else:
            breakdown["操作间隔"] = 10

    # 4. 市场环境(v1.3 改三档:顺势 20 / 中性 10 / 逆势 0,与其他维度对齐)
    pct = market_ctx.get("index_change_pct", 0)
    if trade.action == "buy" and pct > 0.3:
        breakdown["市场环境"] = 20  # 顺势
    elif trade.action == "sell" and pct < -0.3:
        breakdown["市场环境"] = 20  # 顺势
    elif abs(pct) <= 0.3:
        breakdown["市场环境"] = 10  # 中性(横盘)
    else:
        breakdown["市场环境"] = 0   # 逆势

    # 5. 板块热度(简化:基于当日板块涨幅排名)
    if trade.stock_code in market_ctx.get("top5_sector_stocks", []):
        breakdown["板块热度"] = 20
    else:
        breakdown["板块热度"] = 0

    score = max(0, min(100, sum(breakdown.values())))
    return {"score": score, "score_breakdown": breakdown}
```

### 4.7 模块七:今日盈亏估算(v1.5 新增)

> 股民核心诉求:**"今天如果平仓,我会赚/亏多少?"**

#### 4.7.1 输入

- `positions`:持仓列表(代码、股数、加权成本)
- `current_price`:当前价(行情接口)
- `prev_close`:昨日收盘价(行情接口)

#### 4.7.2 算法

```
对每只持仓:
  今日盈亏 = (当前价 - 昨收价) × 股数
  今日盈亏% = (当前价 - 昨收价) / 昨收价 × 100

总盈亏 = Σ 今日盈亏
```

|---|---|
| 持仓卡片 | "今日 +X.XX (+X.XX%)" 醒目行 |
| 首页总览 | "今日总盈亏 X.XX" |
| 计算器 | "今日已盈亏 X.XX"(参考) |

#### 4.7.4 数据源

- 当前价 + 昨收价:AkShare `stock_zh_a_spot_em`
- 缓存:5 分钟(避免重复请求)

### 4.10 模块十:截图识别与录入 ⭐(v2.0 新增)

> **设计目标**:用户核心痛点——手动录入流水成本高,券商 App 截图现成,逐字段重新录入繁琐。让 AI 帮用户"识别截图 → 解析 → 预览 → 入库",**用户只需核对确认**。

#### 4.10.1 触发场景

- 用户在首页 / 设置页 / 流水录入页点击 [📷 上传截图],进入 3 步上传向导
- 用户也可粘贴外网可识图模型的 JSON 输出(降级路径)

#### 4.10.2 支持范围

| 支持 | 不支持 |
|---|---|
| ✅ **同花顺 App**(只此一家) | ❌ 其他券商(华泰 / 招商 / 平安) |
| ✅ 持仓页 | ❌ 资金账户 / 委托单 / 成交回报 |
| ✅ 流水页(成交记录)| ❌ 银行流水 / 信用卡截图 |
| ✅ 自选股页 | ❌ 选股筛选条件截图 |

#### 4.10.3 两种输入路径

##### 主路径:OCR + LLM(隐私友好,推荐)

```
[用户拖拽截图]
   ↓
[后端保存原图到 ~/rich/uploads/{uuid}.jpg(本地,不上传)]
   ↓
[PaddleOCR 离线提取文本]
   ↓
[文本(只数字)传给当前 LLM Provider —— 可能不支持视觉 → 仅文本解析]
   ↓
[LLM 返回结构化 JSON]
   ↓
[前端预览表格(可编辑) + 置信度 + 原始截图缩略图]
   ↓
[用户确认 → 入库 transactions / watchlist]
```

**隐私承诺**:OCR 在本地完成,**只有数字文本**(股票代码 / 股数 / 价格)送给 LLM,原图不上传任何第三方。

##### 降级路径:外网可识图模型 + 我们的 Prompt + 粘贴 JSON

> **场景**:用户当前 Provider 不支持视觉 / 准确度不够 / 想用更专业的视觉模型
> **原则**:**不让任何 Provider 短板阻塞用户**——给用户出路,但保留我们的核心价值(Prompt 模板 + 解析 + 入库)

```
用户在"截图识别"页看到降级提示:
┌──────────────────────────────────────────────┐
│ 你的当前 Provider:DeepSeek · 不支持视觉识别  │
│                                              │
│ 别急:你可以用其他可识图模型                  │
│                                              │
│ 步骤 1:复制 Prompt 模板                     │
│ 步骤 2:把截图发给可识图模型(任选)          │
│   推荐:DeepSeek-VL / 豆包视觉 / Qwen-VL / GPT-4V
│ 步骤 3:把模型的 JSON 输出粘贴到下面         │
│ 步骤 4:解析并预览 → 确认入库                │
└──────────────────────────────────────────────┘
```

#### 4.10.4 Prompt 模板(我们提供,放设置页)

```
[角色]
你是同花顺 App 截图识别专家。

[任务]
从截图中提取结构化持仓 / 流水 / 自选股信息,返回合法 JSON。

[字段定义]
- 持仓:{stock_code(6位), stock_name, shares(int), cost_price(3位小数), market_value(2位小数)}

}

[约束]
- 代码读不清就标 confidence < 0.5
- 价格只取截图中的数字,不要估算
- JSON 必须合法,无尾逗号
```

#### 4.10.5 隐私与安全

- 截图原图**只存本地**(`~/rich/uploads/`),**不上传任何第三方**
- 主路径 LLM **不接收图片**,只接收 OCR 后的数字文本
- 降级路径用户**自决**——是否上传外网模型由用户自己选,我们不背锅
- 截图原图随数据库备份(`backups/`)走,失败迁移时一并保留

#### 4.10.6 边界(PM 第六条边界,v2.0 新增)

```
❌ 多券商(只同花顺)
❌ OCR 自动适配不同 App(只同花顺布局规则)
```

## 第六章 AI Agent 设计(MVP 版)

### 6.1 Agent 矩阵(MVP 只 1 个)

| Agent 名 | 触发场景 | 输入 | 输出 | 模型 |
|---|---|---|---|---|
| **交易诊断 Agent** ⭐ | 每笔交易录入后 | 交易 + 历史 + 持仓 + 市场上下文 + 评分 + **是否在自选股** | 2~3 句评语 | DeepSeek |

### 6.2 多 Provider LLM 调用规范(v1.9 重写)

#### 6.2.1 Provider 矩阵

| Provider | 模型 | 中文 | 成本(参考) | API 兼容 |
|---|---|---|---|---|
| DeepSeek | deepseek-chat | ✅ 强 | ~1 元/百万 token | OpenAI 兼容 |
| MiniMax | abab6.5s-chat | ✅ 强 | ~6 元/百万 token | 自有(需适配) |
| 豆包 | doubao-pro-32k | ✅ 强 | ~0.8 元/百万 token | OpenAI 兼容(火山引擎) |

#### 6.2.2 抽象层

```
BaseLLM(abc.ABC)
   ├── async chat(system, user, temperature, max_retries) -> str
   ├── name() -> str
   └── model_name() -> str

DeepSeekClient(BaseLLM)
MiniMaxClient(BaseLLM)
DoubaoClient(BaseLLM)

ProviderFactory.get(name) -> BaseLLM   # 单例缓存
```

#### 6.2.3 调用流程

```
DiagnoseService.score_and_notify(trade_id)
   ↓
ProviderFactory.get(active_provider).chat(system, prompt)
   ↓
记录 ai_provider / ai_model / ai_latency_ms
   ↓
safe_write 写 trade_scores.ai_comment
```

#### 6.2.4 A/B 测试策略

- **不做"同一笔同时调三家"**(成本 3 倍,违背 A/B 测试控制变量原则)
- **用户在设置页切换 provider**,下次诊断自动用新 provider
- **评分详情弹窗"用 X 模型重新生成评语"**:可针对同一笔换模型重生成,对比 2 个评语
- **不覆盖历史评语**:评语记录当时的 provider/model,切换不影响已有记录

#### 6.2.5 配置(.env)

```
DEEPSEEK_API_KEY=sk-xxx
MINIMAX_API_KEY=xxx
DOUBAO_API_KEY=xxx
LLM_DEFAULT_PROVIDER=deepseek
```

未配置 Key 的 provider 在设置页不可选。

### 6.3 防幻觉约束(写入 Prompt)

- "只基于给定数据回答"
- "无数据时说不知道,不允许编造"
- "所有数字必须与给定数据一致"

### 9.5 失败迁移方案(具体化,v1.8 新增)

> 9.4 定义了"什么时候放弃",本节定义"放弃后数据怎么带走"。原则:**工具可以失败,数据不能被困**。

#### 9.5.1 迁移场景与目标

| 场景 | 目标 |
|---|---|
| 工具停止维护 | 数据可完整导出,格式开放 |
| 换用其他工具(同花顺 / 自研 / stock_project-master) | 导出文件可直接用或经脚本转换 |
| 电脑损坏 / 更换 | 备份文件可恢复,10 分钟内还原 |

#### 9.5.2 三档迁移出口

| 出口 | 文件 | 用途 | 保真度 |
|---|---|---|---|
| 出口 1:CSV | `流水_导出.csv` | Excel/WPS 直接打开继续用 | 高(日期/代码/操作/股数/价格) |
| 出口 2:Excel | `流水_导出.xlsx`(两个 sheet) | 与券商对账、人工分析 | 高 |
| 出口 3:JSON(完整版) | `备份_完整.json` | 还原到 SQLite / 导入其他系统 | 全量(含评分明细与 AI 评语) |

**JSON 数据字典**(字段开放、不加密):

```json
{
  "schema_version": "1.0",
  "exported_at": "2026-08-01T12:00:00",
  "data": {
    "transactions": [
      {
        "id": 1, "stock_code": "000001", "stock_name": "平安银行",
        "action": "buy", "shares": 500, "price": "10.500",
        "trade_date": "2026-07-30", "note": null,
        "score": 72, "score_breakdown": {"集中度": 15, "...": 0}, "ai_comment": "..."
      }
    ],
    "watchlist": [{"stock_code": "000001", "stock_name": "平安银行", "source": "manual"}],
    "stop_losses": [{"stock_code": "000001", "stop_loss_price": "9.500", "enabled": true}]
  }
}
```

> **金额一律以字符串保存**(保留 Decimal 精度),避免 JSON 浮点误差。

#### 9.5.3 迁移步骤(用户手册版)

```
Step 1  设置 → 数据 → 导出 → 选 JSON(完整版)
Step 2  系统校验:导出后自动对账(文件行数 = 数据库记录数,不一致则警告)
Step 3  目标 A:Excel/WPS 打开 → 用 CSV 版
```

### 9.6 AI 评语价值验证(v1.8 新增)

> 评语是**最贵**的功能(每次 LLM 调用花钱),必须验证"用户真的在看、看完觉得有用",否则降频或砍掉。

#### 9.6.1 采集信号

| 信号 | 位置 | 说明 |
|---|---|---|
| 评语展开次数 | 评分详情弹窗 | 不打开评语 = 价值未被消费 |
| 评语阅读时长 | 弹窗打开 → 关闭时间差 | 打开即关 = 没价值 |
| 有用 / 没用 反馈 | 评语末尾两个小按钮 | 主观但有指导性 |
| 重新生成次数 | "重新生成评语"按钮 | 频繁重试 = 评语质量差 |

#### 9.6.2 反馈 UI(不打扰)

- 评语末尾一行小字:`[这条评语对你有用吗? 有用 / 没用]`
- 点击后 1s 消失,不再追问
- 存储:`trade_scores` 表加 `feedback` 字段(Alembic 迁移,枚举 `useful / useless / null`)

#### 9.6.3 目标与决策规则

| 指标 | 目标 | 低于目标时 |
|---|---|---|
| 评语有用率 | > 60% | 改 Prompt(引用更多具体数据) |
| 评语展开率 | > 50% | 评语改 2 句话以内 |
| 平均阅读时长 | > 3s | 同上,去冗长 |

#### 9.6.4 实现位置

- 后端:`trade_scores.feedback` 字段 + `GET /api/feedback/stats`(MVP 可选,先存字段)
- 前端:评分详情弹窗评语区(见 `ui-ux-design.md` 4.4)
- 统计:月度一次,人工看,不建看板

### 12.3 五个子模块详细设计

#### 12.3.1 A1 — 持仓成本联动(K线图版 + 后视镜)

**范围**:仅改 K 线图本身,**不动** PortfolioView、TradeRecordView。

**改造点**:

1. `KlineChart.vue` — props 新增 `costPrice` / `lockProfitPrice` / `stopLossPrice`,渲染 3 条 MarkLine + 1 条成本线
2. 买卖点语义着色:
   - 买入点 > 成本 ×1.05 → 红色"追涨"
   - 买入点 < 成本 ×0.95 → 绿色"抄底/补仓"
   - 卖出点 < 成本 → 红色"割肉"
   - 卖出点 > 成本 ×1.03 → 绿色"盈利落袋"
3. `SignalCard.vue` — 加"成本对照"区 + 追涨/抄底提示
4. **后视镜视角**:同票历史成本价胜率
   ```
   成本价:10.00
     ↳ 历史胜率:60%(过去 10 次做T 中 6 次盈利)
     ↳ 平均盈利:+1.2%,平均亏损:-0.8%
   当前建议买入区间:10.20~10.30
     ↳ 该价位历史胜率:55%(略低于均值)
     ↳ ⭐ 建议:如以 10.50 追涨,历史胜率仅 30%
   ```

**工作量**:2.5d

#### 12.3.2 A2 — 止损/止盈触发器(轮询降级版)

**降级原因**:纯前端方案失去 WebSocket 实时推送,改用前端全局 setInterval 轮询。

**逻辑**:
- 用户在持仓页设置"硬止损价 / 软止盈价",写入 LocalStorage
- 前端全局 setInterval 每 **15s** 拉 `GET /api/v1/portfolio`
- 价格 ≤ 硬止损 → Element Plus Notification 弹窗 + 声音(可关闭)
- 价格 ≥ 软止盈 → 弹窗无声音
- 触发后写入"本地做T记录"(LocalStorage),可后续同步后端

**工作量**:2d

#### 12.3.3 A3 — 信号二次确认

**逻辑**(全部在 signalStore 层):
- **去重**:`sameStock + sameAction within 30min` → 折叠不推送
- **大盘大跌暂停**:指数跌幅 >2% 时暂停推送,UI 顶部提示"市场恐慌,暂停做T信号"
- **用户开关**:"今日已做 T"按钮,当日 signalStore 标记 closed,新信号只展示但不弹窗

**工作量**:1d

#### 12.3.4 A4 — 纪律规则引擎(部分前端)

**行为检测**(纯前端,基于 trade_records API 历史):
- 连续 3 笔亏损 → 弹窗"连续亏损,建议暂停"
- 单日交易 > 3 次 → 弹窗"频繁交易警告"
- 亏损后加倍加仓 → 弹窗"疑似情绪化加仓,红旗 ⚠️"

**规则配置**(写 LocalStorage):
- 单日最多交易次数
- 亏损 N 次后自动锁定(禁止新增交易)N 小时

**禁买时段**:
- 涨停板/跌停板(由行情判断)
- 开盘前 15 分钟 / 收盘前 15 分钟(基于当前时间判断)

**工作量**:2d

#### 12.3.5 C1 — AI 复盘看板

**新增**:路由 `/review`,菜单挂在侧边栏"复盘"分组

**数据来源**:已有 `GET /api/v1/t-focus/{id}/prediction-stats` 取 30/60/90 日准确率

**展示**:
- 3 张折线图(buy_accuracy / sell_accuracy / all)
- 1 个表格(最佳/最差案例)
- Prompt 版本对比("v1.2 比 v1.1 准确率高 X%")

**工作量**:2d
