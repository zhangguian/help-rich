## 第一章 项目概述

### 1.1 项目名称
**盘后诊股室**(Working Title)

### 1.2 一句话定义
一个本地运行的 Web 工具 + AI 解读层,把"我下一笔交易成本会变多少""上下 10% 每个点赚亏多少"这类散户最关心的问题,**用数字算清楚、用大白话讲明白**;并提供盘后自选股监控与选股筛选能力。

### 1.3 立项背景
项目发起人有实盘交易经历,但持续亏损,根本原因不是"行情不好",而是**缺乏系统化分析能力**:
- 不会选股,凭感觉买入
- 看不懂 K 线,凭情绪操作
- 看不懂基本面,踩雷后不知所措
- 不会评估一笔交易/做 T 是否合理,反复犯同样的错误

市面上多数股票软件只提供"数据展示",不提供**交易级别的诊断**。本项目填补"算清交易 + 解释为什么 + 监控 + 选股"这一空缺。

### 1.4 项目目标(MVP 阶段)

| 维度 | 目标 |
|---|---|
| **核心目标** | 让用户在每次交易前/后,都能用 60 秒得到一份"这笔操作值不值得做 / 做完后账户变成什么样"的确定性结论;并在盘后对自选股与候选标的形成系统化认知 |
| **用户量** | 个人自用(单用户、单机) |
| **运行方式** | 本地启动 Web 服务,浏览器访问,无需服务器、无需联网部署 |
| **合规边界** | 仅做分析、不下单;所有 AI 输出附"不构成投资建议"提示;不做真正的盘中实时盯盘(数据延迟 10~15 分钟,定位盘后场景) |

### 1.5 非目标(明确不做)
- ❌ 不接入券商交易接口
- ❌ 不做真正秒级推送的盘中盯盘(只做 15 分钟延迟、1 分钟刷新的盘后自选股监控)
- ❌ 不做多用户系统、账户体系
- ❌ 不做选股自定义条件编辑器(只提供 4 个预设策略)
- ❌ 不计手续费 / 印花税(MVP 之后)
- ❌ 不做云端 SaaS 化(单机本地)

## 第二章 用户与场景

### 2.1 目标用户画像
| 属性 | 描述 |
|---|---|
| 角色 | 有实盘账户的散户,有 1~5 年股龄 |
| 资金量 | 10 万 ~ 100 万 RMB |
| 痛点 | 持续亏损,但不知道为什么亏;缺乏系统化复盘与选股工具 |
| 现有工具 | 同花顺 / 东财 / 雪球(纯查看工具) |
| 期望工具 | 能告诉他"该不该做、做完后会怎样"的诊断助手;能帮他监控自选股、能按策略筛标的 |

### 2.2 三大使用场景

#### 场景 A — 盘前/盘后决策(交易前后)
> "我看好 000001,想加仓 500 股 @ 11 元,做完我成本变成多少?上下 10% 我盈亏多少?"

**触发**:每日上午开盘前 / 盘后复盘
**输出**:交易成本计算器结果 + 21 档盈亏表

#### 场景 B — 盘中做 T(交易中)
> "我持 1000 股 @ 10 元,现价 12 元,卖 500 股做 T,跌到 9 元接回,成本能降到多少?"

**触发**:日内出现明显波动时
**输出**:做 T 完整循环计算 + 已实现盈亏

#### 场景 C — 盘后复盘与监控
> "今天市场怎么样?我持仓的几只逆势还是顺势?这笔操作 AI 怎么评价?我的自选股今天有没有异动?有没有符合策略的新标的?"

**触发**:每日收盘后
**输出**:今日市场速览 + K 线解读 + 单笔交易诊断 + 自选股当日监控 + 选股筛选结果

## 第四章 详细功能设计

### 4.1 模块一:交易流水录入(基础模块)

#### 4.1.1 数据模型

**`transactions` 表**
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | 主键 |
| stock_code | TEXT | NOT NULL | 股票代码,如 000001 |
| stock_name | TEXT | NULL | 股票名称(可从行情接口补) |
| action | TEXT | NOT NULL CHECK IN (buy, sell) | 交易方向 |
| shares | INTEGER | NOT NULL, > 0 | 交易股数(整百) |
| price | DECIMAL(10,3) | NOT NULL, > 0 | 交易价格,3 位小数 |
| trade_date | DATE | NOT NULL | 交易日期 |
| note | TEXT | NULL | 备注 |
| created_at | DATETIME | DEFAULT now | 录入时间 |

**`positions` 视图**(由 transactions 聚合,不持久化)
```
SELECT
  stock_code,
  ANY_VALUE(stock_name) AS stock_name,
  SUM(CASE WHEN action='buy'  THEN  shares ELSE -shares END) AS shares,
  SUM(CASE WHEN action='buy' THEN shares*price ELSE 0 END)
  / NULLIF(SUM(CASE WHEN action='buy' THEN shares ELSE 0 END), 0) AS avg_cost,
  SUM(CASE WHEN action='buy' THEN shares*price ELSE -shares*price END) AS net_cash_flow
FROM transactions
GROUP BY stock_code
HAVING shares > 0;
```

#### 4.1.2 交互

- 表单录入:股票代码自动补全名称、当前价(从行情接口拉)
- 流水列表页:支持修改、删除、按日期/股票筛选
- 持仓概览页:从流水聚合显示,展示每只票的当前股数、加权成本、浮动盈亏

#### 4.1.3 校验

- 卖出股数 ≤ 当前持仓股数(否则提示)
- 价格 > 0、股数 > 0、整百股
- 同一日同一只票的多笔交易允许(支持日内做 T)

### 4.2 模块二:交易成本计算器 ⭐(核心)

#### 4.2.1 输入参数

| 参数 | 类型 | 说明 |
|---|---|---|
| stock_code | TEXT | 目标股票 |
| action | enum | `buy` 或 `sell` |
| tx_shares | int | 本次交易股数 |
| tx_price | decimal | 本次交易价格 |

#### 4.2.2 核心算法(加权平均法,与中国主流券商惯例一致)

**买入**
```
S' = S₀ + S₁
T' = T₀ + (S₁ × P₁)
C' = T' / S'
```

**卖出**
```
S' = S₀ - S₁
C' = C₀                      // 剩余持仓成本不变
已实现盈亏 = (P₁ - C₀) × S₁
T' = T₀ - (S₁ × P₁)         // 总成本相应减少
```

**做 T 完整循环(先卖后买)**
```
视为两笔交易,按上述规则串行计算
做 T 净贡献 = 卖出的已实现盈亏 - (买回部分相对新成本的差额)
```

#### 4.2.3 输出结构

```json
{
  "input": {"stock_code": "000001", "action": "buy", "tx_shares": 500, "tx_price": 11.0},
  "before": {"shares": 1000, "cost_price": 10.0, "total_cost": 10000.0},
  "after": {
    "shares": 1500,
    "cost_price": 10.333,
    "total_cost": 15500.0,
    "delta_cost": 0.333,
    "realized_pnl": 0
  },
  "pnl_grid": [
    {"pct": -10, "price": 9.300, "market_value": 13950.0, "pnl": -1550.0, "pnl_pct": -0.10},
    {"pct":   0, "price": 10.333, "market_value": 15499.5, "pnl": -0.5,    "pnl_pct":  0.00},
    {"pct":  10, "price": 11.366, "market_value": 17049.0, "pnl": 1549.0,  "pnl_pct":  0.10}
  ]
}
```

#### 4.2.4 21 档盈亏表(±10%,每 1% 一档)

| 项 | 说明 |
|---|---|
| 档位数 | 21 档(-10% ~ +10%,含 0) |
| 价格精度 | 3 位小数 |
| 计算基准 | **新成本价 C'**(不是当前市价) |
| 输出字段 | pct, price, market_value, pnl(金额), pnl_pct |
| 可视化 | 横向条形图,0 轴居中,左红右绿 |

#### 4.2.5 边界与异常

| 情况 | 行为 |
|---|---|
| 卖出股数 > 当前持仓 | 返回 422,提示"超过持仓 N 股" |
| 价格 ≤ 0 或股数 ≤ 0 | 返回 422,校验失败 |
| 卖出后股数 = 0 | 新成本返回 null,提示"已清仓",盈亏表仍按 0 股计算(全为 0) |
| 浮点精度 | 全模块使用 `Decimal`,金额 2 位小数,价格 3 位小数 |
| 持仓不存在(从未交易过该票)做买入 | 视为初始建仓,直接用买入价作为成本价 |

### 4.4 模块四:选股筛选器

#### 4.4.1 四个预设策略(MVP 全部实现)

**策略 1:趋势策略**
- 条件:
  - MA5 > MA10 > MA20(多头排列)
  - MACD DIF > DEA 且柱状为正
  - 收盘价 > MA20
  - 排除 ST/*ST
- 预期输出:10~30 只

**策略 2:价值策略**
- 条件:
  - PE(TTM) 在 0~30 区间(可配)
  - PB < 3
  - ROE > 10%(近 4 季度平均)
  - 营收同比增长 > 0
- 预期输出:50~150 只

**策略 3:题材策略**
- 条件:
  - 所属板块当日涨幅排名前 5
  - 个股当日涨幅 ≥ 板块涨幅
  - 个股当日成交量 > 5 日均量 1.5 倍
  - 非 ST
- 预期输出:5~20 只

**策略 4:量价策略**
- 条件:
  - 当日成交量 > 5 日均量 2 倍
  - 当日涨幅 0~5%(温和放量,非追高)
  - 收盘价 > MA20(不在下降趋势中)
- 预期输出:10~40 只

#### 4.4.2 数据模型

**`stocks_master` 表(股票基础信息,启动时初始化)**
```
stock_code, stock_name, industry, market(SH/SZ), list_date, is_st
```

**`daily_quotes` 表(日行情,每日盘后增量更新)**
```
id, stock_code, trade_date, open, high, low, close, volume, amount, turnover
```

**`daily_financials` 表(日财务,每日盘后增量更新)**
```
id, stock_code, trade_date, pe_ttm, pb, roe, revenue_yoy, profit_yoy
```

> 三张表加合适索引后,SQLite 5000 只票 × 250 日/年 ≈ 125 万行/年,**够用**。
> 按 `(stock_code, trade_date)` 联合索引,单只票查询 < 5ms。

#### 4.4.3 数据更新策略

| 任务 | 时机 | 方式 |
|---|---|---|
| 拉股票基础信息 | 启动时一次 | AkShare `stock_info_a_code_name` |
| 拉全市场日行情 | 每个交易日 **15:30 后**(后台任务) | AkShare `stock_zh_a_spot_em` 或历史接口 |
| 拉全市场日财务 | 每个交易日 **15:30 后**(后台任务) | AkShare 财务接口 + 缓存 |
| 数据完整性校验 | 每日更新后 | 缺失日期/股票告警 |

#### 4.4.4 后台任务调度

```
后端启动
  ├─ 初始化 stocks_master(一次性)
  ├─ 启动 APScheduler:
  │    ├─ 每个交易日 15:30  触发:全市场数据更新
  │    ├─ 每个交易日 15:35  触发:预计算技术指标(可选)
  │    └─ 交易日内每 1 分钟  触发:自选股监控刷新
  └─ 提供 /api/admin/refresh 手动触发数据更新
```

**AI 解读(Prompt)**
```
角色:股票分析员
数据:{个股当日行情 + 近 5 日走势 + 所属板块 + 命中该策略的触发条件}
任务:3~5 句话解读,包含:
  1) 为什么被该策略筛出来(命中了哪些条件)
  2) 近期走势特征
  3) 主要风险点(必须包含,不少于 1 句)
```

## 第十章 附录

### 附录 A:核心算法参考实现(Python)

```python
from decimal import Decimal, ROUND_HALF_UP

def calculate_after_transaction(
    shares_before: int,
    cost_before: Decimal,
    action: str,           # "buy" or "sell"
    tx_shares: int,
    tx_price: Decimal,
) -> dict:
    """加权平均法 - 单笔交易后的持仓状态"""
    if tx_shares <= 0:
        raise ValueError("tx_shares must be > 0")
    if tx_price <= 0:
        raise ValueError("tx_price must be > 0")

    total_cost_before = cost_before * shares_before

    if action == "buy":
        new_shares = shares_before + tx_shares
        new_total_cost = total_cost_before + tx_price * tx_shares
        new_cost = new_total_cost / new_shares if new_shares else Decimal(0)
        realized_pnl = Decimal(0)
    elif action == "sell":
        if tx_shares > shares_before:
            raise ValueError(f"Insufficient shares: have {shares_before}, want to sell {tx_shares}")
        new_shares = shares_before - tx_shares
        new_cost = cost_before          # 剩余持仓成本不变
        new_total_cost = total_cost_before - tx_price * tx_shares
        realized_pnl = (tx_price - cost_before) * tx_shares
    else:
        raise ValueError(f"Unknown action: {action}")

    return {
        "shares_before": shares_before,
        "cost_before": cost_before,
        "shares_after": new_shares,
        "cost_after": new_cost.quantize(Decimal("0.001"), rounding=ROUND_HALF_UP) if new_shares else None,
        "total_cost_after": new_total_cost.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP),
        "realized_pnl": realized_pnl.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP),
        "is_closed": new_shares == 0,
    }


def build_pnl_grid(cost_after: Decimal, shares_after: int, pct_range: int = 10) -> list:
    """构建 ±pct_range% 盈亏表,每 1% 一档"""
    rows = []
    for pct in range(-pct_range, pct_range + 1):
        factor = Decimal(1) + Decimal(pct) / Decimal(100)
        price = (cost_after * factor).quantize(Decimal("0.003"), rounding=ROUND_HALF_UP)
        mv = (price * shares_after).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
        pnl = (mv - cost_after * shares_after).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
        rows.append({"pct": pct, "price": price, "market_value": mv, "pnl": pnl})
    return rows
```

### 附录 B:术语表

| 术语 | 含义 |
|---|---|
| 加权平均成本 | 多笔买入的加权平均价,本项目默认算法 |
| 做 T | 当日(或短期内)卖出再买回,降低成本或兑现浮盈 |
| 已实现盈亏 | 已平仓部分的盈亏,落袋为安 |
